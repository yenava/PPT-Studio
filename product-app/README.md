# PPT Studio Product Prototype

This app productizes the local `ppt-design` Skill into a browser workbench.

## Modules

- Workspace: project list, material input, visual preview candidates, confirmation gates, image slide generation, image-based PPTX delivery, and local image refinement.
- Visual style library: reusable styles loaded from `ppt-design/assets/style-templates` plus user-captured styles stored in `localStorage`.

## Real Flow

The prototype now has a local Node API, so the main buttons trigger real workflow actions instead of only mutating mock data:

- `source/`: pasted text and uploaded files are saved under `work/product-app-projects/:id/source/`.
- `outline/ppt-outline.md`: generated by the configured text model.
- `outline/project-profile.json`: generated by the configured text model and used for style-template search.
- `visual/candidates/style-ai-*.png`: generated by the configured image model.
- `visual/pages/pilot/slide-XX.png`: first four high-resolution slide images.
- `visual/pages/pilot/content/slide-XX-content.png`: model-generated body image when hybrid composition is enabled.
- `visual/pages/pilot/slide-XX-composition.json`: deterministic 1920x1080 shell manifest.
- `visual/pages/final/slide-XX.png`: full-deck slide images.
- `pptx/final-image-deck.pptx`: assembled from final slide images.

## Run Locally

Start the Node API server from the project root:

```bash
npm run dev
```

Open:

```text
http://localhost:5173/product-app/
```

If port `5173` is already occupied:

```bash
npm run dev:5174
```

## Configuration

Required for real LLM and image calls:

```bash
export OPENAI_API_KEY="..."
```

Optional overrides:

```bash
export OPENAI_TEXT_MODEL="gpt-5.4-mini"
export OPENAI_IMAGE_MODEL="gpt-image-2"
export OPENAI_BASE_URL="https://api.openai.com/v1"
export OPENAI_IMAGE_BASE_URL="https://apiopencc.com"
export OPENAI_IMAGE_FORMAT="png"
export OPENAI_IMAGE_TIMEOUT_MS="600000"
export PPT_STUDIO_PREVIEW_VARIANTS="1"
export PPT_STUDIO_PYTHON="/Users/yanhui/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3"
```

Image generation uses the project-vendored `$new-imagegen` script:

```text
product-app/scripts/apiopencc_gpt_image_2.py
```

For the `apiopencc` OpenAI-compatible `gpt-image-2` route, set `OPENAI_IMAGE_BASE_URL=https://apiopencc.com` and reuse the same API key.

## Hybrid Composition

The page-generation step supports two modes:

- `hybrid` (default): the image model generates only the content body; `compose_hybrid_slide.py` draws the title, background, footer, and page number into a deterministic 1920x1080 page.
- `full-page`: the image model generates the complete page using the selected master image as a reference.

Cover and ending pages remain full-page generations in hybrid mode. Content pages preserve the model output without cropping and fit it into the fixed shell.

## Debugging

Use:

```bash
npm run check
```

The browser side shows recent run logs in the project detail status panel. The server writes canonical artifacts to `work/product-app-projects/:id/`, so each failed step can be inspected directly.
